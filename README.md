# SuperMario
グループ課題スーパーマリオの共有リポジトリ

＜担当＞
タスクリストの作成者: 梅田
プリプロ版の作成者: 田端

・規則
	変数名はキャメル式で
	新しい敵を作るときはEnemyクラスを継承してEnemyManagerに管理させる
	新しいBlockを作るときはBlockクラスを継承してBlockManagerに管理させる
	コメントを書いて他の人にわかりやすくする

・タスクリストを作成する人用の大まかな概要
	タスクリスト(ID(#00001～)、概要、作成者、担当者、状態(未着手、作業中、PR版提出済み、マージ済み)、工数、かかった時間、優先度)


・新しいタスク作業を始めるとき
	1.developからブランチを作成
	2.feature/develop/[ID]_task_name を生成(developの部分は親のブランチの名前。どこにマージすればいいか分かりやすいためこの命名規則。IDと命名はタスクリストから)
	3.上記でブランチを作成してそのタスクごとに作業を行っていく。

・コミットをする時の規則
	1.作業中の内容なら最初に"[WIP]"を付ける(WIP:Work In Progress)。エラーが出てビルド出来ないなどもこれを付ける。

・タスクが終わった時
	1.GitHubブラウザなどからプルリクエスト(タスクが十分機能してdevelopにマージしたい時に行う。)を提出。
	2.プルリクエストのTitleはブランチ名を入れる。Writesにやった内容、機能を記述。Reviewerに見てもらう人(プリプロ版を作った人は確定)をいれる。
	3.プルリクを提出したら確認して、訂正などがあればそれを返信する。OKならSubmit Viewから確認した人がApprove(マージしていいよという許可)を押す。
	4.許可が下りたらどこかにApproveなどの描画が出るので作業をした人がマージする(developに競合する)。ただし、マージ先に注意(mainにマージすることは基本無し)。


**基本的にdevelopは常に動くことを意識**
